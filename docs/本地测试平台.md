# Q3 本地测试平台

这个平台用于在没有官方模拟器时运行、观察和复现 Q3 策略。它由两部分组成：

- 本地模拟器：监听 `127.0.0.1:2026`，提供 `/enter`、`/measure`、`/clear`、`/exit`。
- 实验仪表盘：显示信号源真值、机器狗轨迹、每次动作、虚拟时间、请求响应和程序输出。

仿真物理规则与 `src/q3_phase3_experiments.py` 的离线批量实验共用同一个实现，便于把可视化调试结果与统计实验互相核对。

## 启动

请先关闭官方模拟器或其他占用 2026 端口的程序，然后在项目根目录运行：

```powershell
python run_local_test_platform.py --open
```

如果不希望自动打开浏览器：

```powershell
python run_local_test_platform.py
```

然后访问 <http://127.0.0.1:2026/>。终端按 `Ctrl+C` 可关闭平台。

可选启动参数：

```text
--port 2026
--seed 20260913
--sources 12
--error-mode hash|minus_one|zero|plus_one
```

现有程序 `src/new/Q3_fast2.py`、`src/experiments/q3/Q3_phase1.py` 和最终入口 `src/new/Q3_active_v2.py` 已固定使用这个地址，因此可以直接从仪表盘运行，也可以在另一个终端手动运行。

如果 2026 端口暂时被官方模拟器占用，可用 `python run_local_test_platform.py --port 2027 --open` 启动。由仪表盘启动的三版程序会自动连接平台实际使用的端口；从另一个终端手动运行时，可先设置环境变量 `CUMCM_SIM_URL=http://127.0.0.1:2027`。

## 常用工作流

### 快速比较三版程序

1. 填写随机种子、信号源数量和误差模式。
2. 选择一个 Q3 版本，点击“创建场景并运行”。
3. 查看路径、清除结果、虚拟耗时和程序日志。
4. 勾选“沿用当前信号源位置”，依次运行另外两个版本。

“沿用”会保留完全相同的信号源坐标与接收半径，同时清空上一版的机器人状态、请求和日志，保证公平对比。

### 运行 12 个种子并计算平均用时

在“运行模式”中选择“全部运行”，再选择需要评估的某一版程序。平台会让该版本依次运行从当前起始种子开始的 12 个不同种子，并显示逐局进度、完整清除局数、平均动作数和平均虚拟用时。该模式只评估所选版本，不会自动运行其他版本。

### 调试异常路径

- “每 N 次动作断网一次”会直接中断对应 HTTP 连接，用于验证相同 `request_id` 的重试逻辑。
- “每频道首次清除强制失败”用于验证重定位和兜底清除逻辑。
- 测向误差可固定为 `-1°`、`0°`、`+1°`，便于复现几何边界。
- “手动接口调试”可单独发送进入、测量、清除和退出请求。

### 保存与复现

“导出本局”会保存一个 JSON 文件，其中包含：

- 完整信号源真值与场景配置；
- 所有动作及其虚拟耗时；
- 原始 HTTP 请求和响应；
- 程序标准输出与最终汇总指标。

之后用“导入复现”载入该文件，并保持“沿用当前信号源位置”勾选，即可在相同场景上重新运行。

## 本地管理接口

仪表盘使用以下本地接口，便于后续脚本化：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/health` | 存活检查 |
| GET | `/api/state` | 当前场景、动作、指标和输出 |
| GET | `/api/export` | 导出完整实验 JSON |
| POST | `/api/scenario` | 创建或导入场景 |
| POST | `/api/run` | 运行白名单内的 Q3 版本 |
| POST | `/api/stop` | 停止当前程序 |

服务器只绑定本机回环地址，不向局域网或公网开放，也不会自动上传任何实验数据。

## 与官方模拟器的边界

平台复现了本题当前文档中的全向信号源、接收半径、测向误差、移动/切换/动作耗时、清除半径、请求幂等和主要字段校验。它用于开发期快速反馈，不能替代最终在官方模拟器上的验收；若官方规则或隐藏实现更新，应同步修改离线仿真并重新跑回归实验。
